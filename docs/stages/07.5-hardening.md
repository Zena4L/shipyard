# Stage 7.5 notes: hardening

The engineering record of stage 7.5, a step between stages 7 and 8: what a review of the
whole codebase found after stage 7, what was fixed and how, what was decided not to fix,
and what's left. The open items are tracked in the [ROADMAP](../ROADMAP.md#open-findings).

## Outcome

After stage 7, five reviewers each audited one area of the codebase. The highest-impact
findings were re-checked by hand, and the rest by independent agents, which corrected
several (the severities below are the corrected ones). The reviewers scored:

- the process lifecycle, isolation, resource control and images 7/10 each;
- networking 6/10.

Stage 7.5 fixed every finding that untrusted input could reach. Two constraints from the
user held throughout: no breaking changes and no regressions. Where a fix would have
broken something that works today, the decision went to a warning instead (D1, D3, D8,
D9, D12).

## Decisions and why

The recommendations were accepted on 2026-10-09:

- **D1:** without a device program, drop `CAP_MKNOD` and warn. Refusing to run would
  break cgroup-v1 hosts; a `nodev` `/dev` would break the nodes Shipyard makes (probe 10).
  A root filesystem's own device nodes still open. The warning says so, and `nodev` on
  the root would break bundles that rely on theirs.
- **D2:** a memfd that can't run falls back to the binary's file, with a warning.
- **D3:** a rootful run on the host's `/` warns; a required flag waits for a major version.
- **D4:** inherited metadata is kept; only extractions that inherited any get the
  lowers-specific name, so existing stores stay valid.
- **D5:** at most 128 layers per image, as Docker builds them.
- **D6:** the fix goes in the built-in profile's data; a bundle's profile keeps exact
  64-bit semantics.
- **D7:** anti-spoofing goes in a `bridge`-family table of its own: its own batch and
  version, never failing the `inet` table, and never filtering a port it doesn't know.
- **D8, D9:** warn, don't refuse.
- **D10:** a per-source conntrack limit is deferred to stage 9, as an option.
- **D11:** F16 closed with a bound test.
- **D12:** no deadlines on the init's and monitor's waits; a deadline would end hooks the
  OCI spec lets run.

## Validation note

Two agents built 7.5a to 7.5e, and stopped (rate limits) before recording 7.5e. While one
was still editing, Linux runs failed for reasons that turned out to be stale build
artifacts, not code. Once the tree held still and the workspace crates were rebuilt from
clean, every run passed. Lesson: never validate a tree that's still changing.

## Stage 7.6: the rest of stages 1–7

The review's findings that belong to stages 1–7, and that hadn't made 7.5's table, were
added to the ROADMAP as F17–F31. Stage 7.6 fixed the ones that could be done before
stage 8:

| Finding | What could happen | Fixed by | Tested by |
|---|---|---|---|
| F18, low | a CI action's tag moved to other code | every action pinned by commit, its version beside it | (CI) |
| F19, low | `update --cpu-quota` alone reset the period to 100 ms | `cpu.max` gets the quota alone; the kernel keeps the period | `a_quota_alone_keeps_the_period` |
| F20, low | the host's OOM killer, or a parent cgroup's limit, reported as the container's own "out of memory" | `memory.events`' `oom` (its own limit hit) against `oom_kill`: "the host or a parent cgroup ran out of memory" | `an_oom_kill_without_the_limit_hit_was_from_outside` |
| F21, low | `--blkio-weight` silently did nothing (iocost off, the default) | a warning when no disk has `enable=1` in the root's `io.cost.qos` | `an_io_weight_needs_iocost_on` |
| F22, low | any user could lock a dead run's directory, so it was never swept | the lock is a 0600 file inside; the directory's lock is held too, for an older Shipyard's sweep | `the_sweep_goes_by_each_runs_own_lock_file` |
| F23, low | after a firewall rebuild, published ports were briefly missing | the ports in the table's own batch when it fits 64 KiB; the table alone first if a port is refused | `ports_go_in_the_tables_batch_while_they_fit`, `many_ports_install_with_the_table_or_after_it`, `a_refused_port_leaves_the_table_installed` |
| F25, medium | a token request's credentials followed a redirect to another host | no redirects for a token request with credentials; a 3xx is refused, saying why | `credentials_never_follow_a_token_services_redirect` (password and identity token) |
| F26, low | a symlink in an image steered a volume onto `/dev/pts`, `/dev/mqueue` or the cgroup tree | those file systems refused too, unless the destination names that place; an `fstatfs` that fails refuses | `a_destination_led_into_a_kernel_interface_is_refused_and_one_named_isnt` |
| F27, low | before Linux 5.14, a fork bomb outran a kill PID by PID | freeze, kill each, thaw (a paused container stays frozen) | `a_forking_cgroup_is_killed_frozen` |
| F28, low | a `create` killed between making the cgroup and recording it left it behind for good | the cgroup recorded as pending before it's made; `delete` removes a pending one with `rmdir` only | `delete_removes_a_killed_creates_pending_cgroup` |

**Decisions:**
- **F28 changed in the build.** The plan was for `create` to remove a leftover at
  the ID's default path. That path is shared by every `--root`, though, so the
  "leftover" could be another root's live container, killed or shared. Recording the
  cgroup first, and `delete` removing a pending one only if the kernel agrees it's
  empty, never kills anything.
- **F24 waits** (later): the fix means carrying a descriptor for every bind source
  through the init's re-exec. The attack needs write access above another bundle's
  source, and runc has the same gap.
- **F25 warns about no realm:** Docker Hub's token service is on another domain
  (`auth.docker.io`), so a warning would fire for everyone.

**What the reviews found:**
- **The clean-code review:**
  - `create` dropped the limits' warnings;
  - the OOM cause ignored parent cgroups' limits;
  - the I/O-weight check warned falsely inside a cgroup namespace;
  - the mount guard failed open when `fstatfs` failed;
  - duplication: `CpuMax::from_parts`, one `flock` helper, `KERNEL_INTERFACES`;
  - the anonymous control didn't check the pull, and the freeze test placed its shell
    late.
- **The Murphy review:**
  - BFQ never reads `io.weight`, so the check is now on iocost alone;
  - a kill thawed a paused container;
  - one refused port took the whole table down;
  - an older Shipyard's sweep would remove a new run's live directory.

**Residuals** (in F31):
- BFQ's `io.bfq.weight` isn't written;
- `update --cpu-period` alone clears the quota;
- a host OOM kill after the container once hit its limit still reads "out of memory";
- securityfs and the like below a bundle's own recursive `/sys` bind aren't refused;
- a `delete` of a killed `create` can `rmdir` another root's same-ID cgroup in the
  instant before its init joins it, so that `create` fails;
- downgrading below 7.6 reads a pending cgroup as made.

## Carried forward

- **F6** (stage 8, `exec`): a joined process must be confined, non-dumpable before
  `setns`, with no host procfs descriptors.
- **F14** (stage 8, with real-host CI): firewalld and Docker coexistence.
- **F10's per-source conntrack limit** (stage 9, D10).
- **F17, F18** (stages 8–9): the low items, and CI hardening (actions pinned by commit,
  more distributions, fuzzing and mutation in CI).
- **The bridge table:**
  - link-local IPv6 isn't tied to the container;
  - containers that route, bridge or tunnel for others, or use other ethertypes, are cut
    off on a guarded port (documented);
  - `release_lease` probes the table before unguarding.
- **The sealed copy:** about 3.5 MB of memory per container in release builds;
  SELinux/AppArmor policy on memfd exec unverified until the VM CI (H4).
